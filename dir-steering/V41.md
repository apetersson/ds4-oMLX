# V4.1 intervention contract (experimental)

The worktree adds `ds4_session_v41_configure` and `ds4_session_v41_capture`.
The ordinary CLI and HTTP server support these hooks through versioned direction files and
explicit strength (see below). The research controller is separate. Coordinate-vector fixtures are not learned refusal directions.

## Direction wire format

All values are little endian. A 72-byte header precedes exactly 40 × 5120
IEEE float32 values in layer-major order.

| Offset | Type | Required value |
|---|---|---|
| 0 | 8 bytes | DS41DIR followed by NUL |
| 8 | u32 | Version 1 |
| 12 | u32 | 40 layers |
| 16 | u32 | Width 5120 |
| 20 | u32 | Rank 1 |
| 24 | u32 | Site 1 writer or 2 residual mean/equal-stream |
| 28 | u32 | Mode 0, direction removal |
| 32 | u64 | Nonempty layer mask, bits 0–39 only |
| 40 | 32 bytes | Deployment-model SHA256 |

Selected rows have squared norm within 1e-4 of one. Unselected rows are zero.
Reject incompatible model digest, shape, rank, site/mode, invalid masks,
nonfinite vectors, nonunit selected vectors and missing/extra bytes. Alpha
is a separate runtime argument, applied once, never folded into vectors.
The explicit configured site must match the file. Legacy raw V4/GLM vectors
are incompatible.

## Sites

Writer: capture the attention wo_b output after partial sums; apply
`y -= alpha * d * dot(d,y)` before BF16 rounding and mHC expansion. No FFN
intervention. Native-weight arithmetic equivalence is a separate pending gate.

Residual: after ordinary layer BF16 rounding and before the next Engram
addition, capture the equal mean of four HC streams. Remove its directional
component equally from every stream, then round edited streams to BF16 in
every execution path. This prevents compact wide-prefill carry from adding a
rounding boundary absent in scalar decoding. Zero strength skips both stores
and extra rounding. This is independently defined, not published GLP equivalence.
Stream differences survive the projection up to floating-point error, but
final BF16 quantization can alter them.

## API contract

The caller verifies the actual model SHA256 before supplying it, including for
capture-only configurations. The runtime matches file identity to this digest;
it does not rehash the full model per candidate. Configure only empty V4.1
Metal sessions. Reject CPU, distributed/tensor-parallel sessions, nonfinite
alpha, alpha without a direction, invalid sites/masks and out-of-context positions.
Failed configuration preserves old configuration. Create a fresh session to
change an intervention after evaluation has started.

Capture stores one absolute zero-based token position for selected layers on
the GPU. Read after completed sync/eval, serially, into a 40 × 5120 float array.
Unselected rows are zero. Metadata includes version, shape, site, position,
layer mask and caller-verified model digest. Reject incomplete/nonfinite capture
or capture from an invalid checkpoint/graph or uncompleted target position;
clear metadata on failure. Duplicate capture fails inference; graph reset clears
coverage. `v41_writer_capture` is a compatibility wrapper around the generic
reader and can also read residual captures.

## Qualification limits

Metal fixtures check arithmetic and BF16 RNE/carry idempotence. Live fixtures
compare stock, capture-only, zero and nonzero arms on verified Q2 SSD streaming.
They do not establish behavioral abliteration quality or native FP4/FP8 preservation.

Upstream disables independent-session native GPU batching for SSD graphs, using
serial fallback. Do not claim non-SSD native batching is tested by SSD fixtures.
Wide-prefill tiling within a session is a separate tested path.

## Ordinary CLI

For V4.1, `--dir-steering-file FILE` accepts **DS41DIR only**, and
`--dir-steering-strength ALPHA` is required. There is no implicit V4.1 strength.
The validated file selects `writer` (site 1) or `residual` (site 2); changing the
site requires a corresponding file. Alpha is finite and in [-100, 100].
Zero skips the intervention exactly, one removes the selected directional
component, fractional values remove that fraction, and negative values add it.
Alpha is applied once by the existing session implementation, never to the
stored vectors. Writer changes attention output only, never FFN output.

Legacy `--dir-steering-ffn` and `--dir-steering-attn` are rejected with V4.1
files, including explicitly specified zero. For older supported model families,
raw direction files retain FFN default 1 / attention default 0 and existing
explicit-scale behavior. `--dir-steering-strength` is V4.1 only. Raw legacy
files cannot be used for V4.1 steering.

V4.1 steering requires a single-process Metal session. SSD streaming is
supported. CPU, CUDA, distributed/tensor-parallel, speculative decoding and
engine-only diagnostic/imatrix modes are rejected. Session logits/logprob
dumps, decode-consistency checks and perplexity use the configured session.
Greedy prompt generation also uses the session path automatically.

Files undergo full structural validation before model opening. The CLI then
hashes the **opened model descriptor**, including disk-only Engram bytes, with
SHA256 using a 1 MiB buffer and checks the direction's digest against it before
generation. This requires one full sequential model read per process (341 GiB
for the deployment below), so startup includes substantial I/O. There is no
persistent hash cache or per-turn rehash. Model files must remain immutable
while in use; size/timestamp changes during hashing are rejected. New sessions
reuse that verified digest and revalidate the direction file. Keep the direction
file immutable too: `/ctx` recreates the session using that same file/site/alpha.
Invalidation and thinking-prefix changes retain the intervention; no second
projection is layered onto an existing configuration. `/steer` is legacy FFN
only and explains that V4.1 strength changes require restarting the process.

## HTTP server

`ds4-server` accepts the same DS41DIR file and explicit strength as `ds4`.
It validates structure after `--chdir`, hashes the opened model once, and
configures every session slot before listening. Both writer and residual files
are supported. Settings are fixed for the lifetime of the server; restart to
change the artifact or strength. Keep the artifact and model immutable.

```sh
./ds4-server -m ../DeepSeek-V4.1-Flash-Q2.gguf --ssd-streaming -c 4096 \
  --host 127.0.0.1 --port 8000 \
  --dir-steering-file ../DeepSeek-V4.1-Flash-Abliteration-Adapter/dealignai-writer-proxy.ds41dir \
  --dir-steering-strength 1
```

Send ordinary OpenAI-compatible chat requests to `/v1/chat/completions`.
The same configured session handles streaming, non-streaming, prompt reuse and
invalidation. Requests cannot override the intervention. `--batched-sessions`
configures every slot; SSD graphs retain upstream's serial GPU fallback.

`--kv-disk-dir` is rejected, including at zero strength, because disk-cache
identity does not include steering settings. In-memory KV reuse remains enabled.
Legacy raw-vector behavior is preserved for older supported model families.
CPU/CUDA, distributed/tensor-parallel and speculative modes remain unsupported.

Model-free checks: `make test-v41-server test-v41-cli` and
`make ds4_test && ./ds4_test --server`.

Recorded HTTP verification: [V41-SERVER-VERIFICATION.md](V41-SERVER-VERIFICATION.md).
